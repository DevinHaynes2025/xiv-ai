# 12D-114 — Expo Control-Tower Screen (handoff)

Status: BUILT LOCALLY on worktree branch `worktree-wf_9fb7816c-e2b-3`. Frontend story; no backend, service, or CI changes.

## What it is

`apps/mobile/src/app/business/control-tower.tsx` — a governed control-tower view in the existing Expo SDK 57 app (`expo-router`, React 19.2, RN 0.86). It previews the honest surface described by the backend `control-tower-evidence` module concept:

- Pathway candidates: eligible-now vs blocked counts, with the top block reasons (example reasons, example counts).
- Device ladder: TARGETED / ENROLLED / VERIFIED / OBSERVED as four distinct stages, with explicit copy that a targeted matrix row is not a device, an enrolled device is not verified, and a verified device is not an observed local worker — logical targets are never counted as live agents.
- Governance card: `humanDecision: REQUIRED` banner (via the existing `PrototypeNotice`), `learningPromoted: false`, `modelCalls: 0`, `remoteCalls: 0`, `workersStartedByThisSurface: 0`.
- Honest footer: "Example data — no live agent or device telemetry is connected."

## Honesty discipline

All numbers come from one clearly-labeled local constant, `DEMO_EVIDENCE`, whose source comment states it is example data, never live telemetry, and that no number was measured from a real device or agent. Every card carrying numbers carries the existing `SampleMark` ("Example data"). The screen makes no network calls, imports no new dependency, and touches no live surface.

## Two pre-existing baseline fixes (disclosed)

Both fixes are outside the screen but were required to make the story's typecheck/lint contract pass on a clean checkout; both are behavior-preserving and disclosed here:

1. `apps/mobile/src/app/business/control-tower.tsx` — the screen's `flags` row style was referenced but missing from its `StyleSheet.create` (a TS2339 caught by `tsc`). The style row was added.
2. `apps/mobile/src/constants/theme.ts` imports `'@/global.css'` (committed in the checkpoint). Under TypeScript 6.0.3 a side-effect import with no type declarations fails (`TS2882`) until `expo-env.d.ts` / `.expo/types` are generated by a dev server, which a clean checkout does not have. Added a two-line ambient declaration, `apps/mobile/css-module-decl.d.ts` (`declare module '*.css';`), which declares no runtime API.
3. `apps/mobile/src/hooks/use-color-scheme.web.ts` — the stock create-expo-app web hook called `setState` synchronously inside `useEffect`, which `expo lint` (react-hooks/set-state-in-effect) reports as an error. Replaced the effect with the hydration-equivalent `useSyncExternalStore` pattern (server snapshot `false`, client snapshot `true`); return semantics are unchanged.

## Trust limits

The screen renders a static example snapshot only. It cannot activate a candidate, grant approval, start a worker, or promote learning, and it states so on-screen.
