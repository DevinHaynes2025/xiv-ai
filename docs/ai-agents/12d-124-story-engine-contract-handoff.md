# 12D-124 — Governed Story Engine backend contract (handoff)

Status: BUILT LOCALLY on `claude/12d-99-supervised-local-worker`. Completes the master
plan's investor-demo trio on the backend side: GOVERNED AGENT (12D-121, done), STORY
ENGINE frontend (12D-122, done), STORY ENGINE backend (this contract).

## What it is

`story-engine-contract.ts` is the GOVERNANCE ENVELOPE for a story — explicitly NOT a
story generator:

- A KPI change arrives as a DECLARED signal (`source: 'DECLARED_METRIC_CHANGE'` — the
  only accepted source; anything claiming to be model-detected or inferred fails
  closed). The context lines and the narrative are DECLARED/authored, never generated
  — no model call exists in this runtime.
- `composeGovernedStory` wraps them in a frozen packet on the exact 12D-122 ladder
  SIGNAL → CONTEXT → STORY → TREATMENT → ACTION → LEARNING, with a deterministic
  sha256 `storyId` over (metricId | direction | declaredAtMs | narrative), every
  treatment stamped `REQUIRES_HUMAN_APPROVAL`, `storiesFromLiveData: 0` (structural,
  not aspirational), and the canonical frozen guardrails + honest flag set.
- `assertStoryInvariants` is the mechanical tamper check: canonical frozen guardrails
  (reference equality, so fabricated lookalikes fail), exact ladder, every treatment
  requiring human approval, learning never promoted, full constitution flags. Used by
  construction itself (the constructor ships no story it would reject), by tests, and
  by any future surface.
- `recordTreatmentDecision` records the HUMAN decision on a treatment — receipt-gated
  (64-hex sha256 operator receipt, the 12D-119/12D-121 discipline), chronologically
  ordered (a decision timestamp predating the declared signal fails closed — the 12D-121
  rule), and self-describing (the record carries the treatment DESCRIPTION alongside
  its id, so it evidences exactly which treatment text the human decided on). Its
  `requiresDecisionSafetyWorkflowBeforeAnyAction: true` flag is a REQUIREMENT, not a
  past-tense claim: this runtime opens no 12D-121 workflow and routes nothing — any
  resulting action MUST pass one first, in a system outside this runtime. A DECLINE is
  recorded verbatim. Neither promotes learning and neither executes anything.

## Honest state

Every story carries `humanDecision: 'REQUIRED'`, `learningPromoted: false`,
`modelCalls: 0`, `remoteCalls: 0`, `storiesFromLiveData: 0`, `automaticRecovery: false`,
`billionUsersProven: false`. Guardrails:
`storiesAreDeclaredNotInferred`, `narrativesAreAuthoredNotGenerated`,
`everyTreatmentRequiresHumanDecision`, `learningIsNeverPromoted`, `executesNothing`.
Zero network calls (pure module) — 12D-113's authorized-surface audit applies.

## What this does NOT claim

No story here comes from live data — `storiesFromLiveData` is structurally 0 because
no live metric is connected to this contract. No narrative was generated by any model.
No action is executed by this runtime; a decision record only routes a human-approved
treatment toward the 12D-121 workflow. `billionUsersProven: false`.

## Trust limits

The contract authorizes nothing and executes nothing. An accepted decision record is a
REQUIREMENT that a 12D-121 gate ladder must be passed before any action — never an
instruction, never a claim that a workflow exists. The frontend (12D-122) shows
example data only; connecting any real metric source is future work requiring its own
review, and the moment live metrics feed signals, `storiesFromLiveData` becomes a
measured number this contract still reports honestly.

## Adversarial review (paydown record)

9-agent review workflow (2 lenses — semantics/security + governance/honesty — every
finding adversarially verified by independent verifiers with live tsx reproduction;
6 verifier-stall retries during classifier instability, never bypassed): **7 confirmed
findings (4 BLOCKING, 3 CONSERVATIVE, deduplicating to 5 distinct defects), 0
refuted. All fixed before commit; tests re-run 5/5 and typecheck PASS.**

- BLOCKING (live-reproduced): the storyId preimage hashed only
  (metricId|direction|declaredAtMs|narrative) — omitting the declared MAGNITUDE (the
  KPI change the module exists to narrate), the declarer, the context, and the
  treatments. Two stories differing only in magnitude ("fell 0.1%, noise" vs
  "collapsed 90%") and treatments collided byte-for-byte, so a receipt-backed
  decision on the benign treatment was indistinguishable from a decision on the
  hostile one — the exact transplant class 12D-121 closes with proposalDigest.
  FIXED: `deriveStoryId` now hashes a canonical JSON serialization of EVERY declared
  input (fixed key order, no delimiter-injection surface), shared by the constructor
  and the invariant check.
- BLOCKING (live-reproduced): `assertStoryInvariants` never read `story.storyId` —
  no hex64 check, no re-derivation. A forged packet with any foreign or non-hex
  storyId passed every invariant and `recordTreatmentDecision` copied the forged id
  verbatim into the receipt-backed record. FIXED: the invariant check re-derives the
  storyId from the declared content and requires exact match (enforcing the 64-hex
  format at the same time). Regression tests added (non-hex id, foreign id
  transplant, content-swapped transplant on both paths).
- BLOCKING (live-reproduced): the decision record stamped
  `routedToDecisionSafetyWorkflow: true` as a static literal — including on
  DECLINED records — a past-tense claim of routing the runtime never performs (no
  workflow is opened or referenced anywhere). Sibling packets carry only honest
  negative claims; this was the inverse pattern. FIXED: renamed to
  `requiresDecisionSafetyWorkflowBeforeAnyAction: true` — a requirement declaration,
  truthful on both accept and decline records.
- CONSERVATIVE (live-reproduced): `decidedAtMs` was accepted with no temporal
  ordering — a receipt-stamped record could assert a human decided BEFORE the signal
  was declared (backfilled approval). FIXED: `decidedAtMs < declaredAtMs` fails
  closed (the 12D-121 rule). Regression tests added.
- CONSERVATIVE (live-reproduced): the deterministic-storyId test contained a vacuous
  assertion (`changed` was the identical story) and a confounded case (two variables
  changed at once), so the under-inclusive preimage passed 5/5 green. FIXED:
  single-variable isolation for every declared input, the vacuous lines removed, and
  the benign-vs-hostile collision scenario asserted verbatim. (This test fix is what
  would have caught the BLOCKING collision pre-commit.)

Residual disclosed: the requirement flag is declarative — this contract cannot
verify that a 12D-121 workflow was ever actually opened for an accepted treatment.
Binding a real `decisionSafetyWorkflowId` into the record would require coupling this
pure envelope to the 12D-121 module (or an adoption layer that links them); that is
future work, and until then the record's honesty rests on the requirement wording
plus `executedByThisRuntime: false` / `productionExecutionAllowed: false`.
