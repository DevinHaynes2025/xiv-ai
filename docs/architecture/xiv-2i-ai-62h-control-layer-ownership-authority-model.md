## Governing Principle

```
OWNERSHIP ≠ UNLIMITED AUTHORITY
```

Each layer owns a bounded control domain. Ownership confers **stewardship and named duties** inside that domain — not a blank check to override, absorb, or silently elevate into another layer’s domain.

**Hard honesty:**
- Named ownership ≠ permanent absolute power  
- Delegation ≠ surrender of consequence  
- Presence in a layer ≠ authority of that layer  
- Automation ≠ approval  
- Intelligence ≠ authority  
- Docs / queue checkmarks ≠ IMPLEMENTED / ≠ VERIFIED / ≠ DEPLOYMENT AUTHORIZED

## Scope Rule

**No automatic elevation across layers.**

- Authority granted at layer *N* does **not** imply authority at layer *N+1* or *N−1*.  
- Galaxy coordination ≠ Universe admin.  
- Constellation membership ≠ permission grant.  
- Task Force lease ≠ Universe ownership.  
- Agent assignment ≠ Human consequence ownership.  
- Model/tool/runtime capability ≠ any authority layer.  
- Cross-layer action requires an explicit **Delegation Contract** (below) + dual gates where required.

## Delegation Contract

Every cross-layer or consequential delegation MUST carry:

| Field | Required | Notes |
|-------|----------|-------|
| `delegation_id` | YES | Stable id |
| `from_layer` / `from_owner` | YES | Named owner identity |
| `to_layer` / `to_principal` | YES | Recipient — never anonymous |
| `purpose` | YES | Bound purpose string |
| `scope` | YES | Resources / actions / Universes / constellations |
| `authority_ceiling` | YES | Hard ceiling; not self-raisable |
| `allow_set` / `deny_set` | YES | Explicit; DENY wins on conflict |
| `dual_authorization` | YES when federated | Both sides required |
| `guardian_constraints` | YES | Non-bypassable |
| `budget_binding` | YES when spend/compute | Cost ownership map |
| `evidence_requirements` | YES when gating | Exact-commit / strength |
| `starts_at` / `expires_at` | YES | Temporary-by-default |
| `revoke_path` | YES | Who can revoke + how |
| `audit_ledger_id` | YES | Decision Ledger reference |
| `emergency_flag` | YES | Default false; see Emergency Authority |
| `status` | YES | PROPOSED / ACTIVE / EXPIRED / REVOKED / DENIED |

Missing required field → contract **INVALID** → treat as **DENY**.

## Security Decision Recording Requirements

Every security-affecting decision MUST record:

1. `decision_id`, UTC timestamps  
2. Actor identity + layer  
3. Authority basis (policy id / Delegation Contract / Human grant / Guardian rule)

5. Scope affected (Universe / constellation / runtime / identity)  
6. Evidence refs (exact commit when gating)  
7. Kill/budget/identity side effects  
8. Reviewer / dual-auth party when required  
9. Expiry / revoke path  
10. Ledger append confirmation  

Unrecorded consequential security acts are **defects** — treat subsequent dependent actions as **DENY** until remediated.
