## Architecture contracts (story §§1–101)

### 1. Compact Architecture Overview

See diagram above. Compact Architecture is the controlling map for this park; detailed sections expand contracts without authorizing runtime.

### 2. XAAF — XIV Adaptive Agent Foundry

**XAAF** is the governed plane for proposing, composing, instantiating, hibernating, promoting, and retiring **bounded temporary specialist agents**.

- Foundry proposes; Guardian + Creation Contract authorize.
- Foundry never self-expands its own authority.
- Foundry ≠ unbounded spawn factory.
- `XAAF_ENABLED=false` in this park.

### 3. Reuse Before Creation

Before any create path:

1. Search Blueprint Registry for matching specialist.
2. Prefer wake of hibernated agent with compatible capability set.
3. Prefer attach to existing Dynamic Task Force.
4. Prefer Capability Composer remapping over new identity.
5. Only then open Creation Contract proposal.

**Metric intent:** Creation Efficiency (reuse hits / create proposals) — engineering goal, not claimed PASS.

### 4. Creation Contract

Every instantiation requires an explicit **Creation Contract** including:

- requester / purpose / parent lineage
- capability ceiling (≤ requester; never above)
- TTL / hibernate / destroy policy
- budget (tokens, GPU, curiosity, tool calls)
- AuthZ scope inherits; no expansion
- approval class (auto-sim vs human/Founder)
- audit + provenance anchors

Missing or UNKNOWN fields → **DENY-safe**.

### 5. No Unlimited Descendants

- Hard max descendant depth (document intent; default deny if unset)
- Hard fan-out per parent per window
- Recursive create of creators **forbidden** (`AUTO_AGENT_REPLICATION=false`)
- Cycle Detector participates in lineage graph checks

### 6. Lineage

Every agent carries immutable lineage: parent, contract id, blueprint id, birth reason, capability ceiling snapshot, creator principal.

- Lineage is auditable; tampering = security fail
- Orphan agents without lineage = reject / quarantine (future harness)

### 7. Population Governor V2

Extends prior population controls:

| Control | Intent |
|---------|--------|
| Logical population ceiling | simulation envelope |
| Concurrent ephemeral ceiling | wake/active bound |
| Create rate limit | anti-storm |
| Gap pool size | pre-warmed reusable slots |
| Task Force count ceiling | composition bound |

Governor **denies** create when ceilings would breach. Governor cannot grant permissions.

### 8. Ephemeral lifecycle

States (document): `PROPOSED → CONTRACTED → WARMING → ACTIVE → IDLE → HIBERNATED → DESTROYED` (+ `PROMOTED` branch).

- Wake for work; hibernate when idle
- TTL expiry → hibernate or destroy per contract
- Ephemeral default; promotion is explicit gate

### 9. Promotion

Promotion to longer-lived / blueprint-catalog status requires:

- evidence pack
- security review intents
- Founder / human approval class when crossing trust boundary
- **Promotion ≠ permission expansion**

### 10. Blueprint Registry

Catalog of reusable specialist blueprints: skills, tools (declared), model class prefs, default budgets, required AuthZ templates.

- Registry entry ≠ enabled runtime agent
- Unlisted tool/model references remain unavailable until separately authorized stories

### 11. Capability Composer

Composes capability sets from blueprints + task needs **within** AuthZ ceiling.

- Composition cannot invent new permissions
- Unknown capability → exclude / DENY path, not silent allow

### 12. Dynamic Task Force

Temporary multi-agent composition for a mission:

- members bounded by Population Governor
- shared mission contract; no shared privilege elevation
- dissolves on mission end; members hibernate/destroy per contract

### 13. XIP — Intelligence Pipeline

**XIP** orchestrates multi-step reasoning / research / synthesis graphs under budgets and safety nodes.

`XIP_ENABLED=false` here.

### 14. Pipeline Graph

Nodes = steps (retrieve, reason, critique, simulate, brief). Edges = data/control with provenance.

- Graphs are versioned templates (Pipeline Studio)
- Cycles require Cycle Detector waiver class (default deny unbounded loops)

### 15. Loop Optimization (safety-preserving)

Optimizer may remove redundant compute **only if** it does **not** remove or weaken:

- AuthZ checks
- Guardian evaluations
- RLS / tenant isolation
- classification gates
- human / Founder approval nodes
- audit emission
- provenance attachment

Any optimizer proposal that touches those classes → **reject** or require explicit human approval story (not this park).

### 16. Cycle Detector

Detects reasoning loops, agent create loops, pipeline cycles, and overnight research loops.

- Soft warn vs hard stop classes
- Create-loop → hard stop (`AUTO_AGENT_REPLICATION=false`)

### 17. Reasoning Budget

Per-agent / per-pipeline / per-night budgets: tokens, wall time, tool calls, GPU seconds, curiosity units.

Exhausted budget → graceful stop + brief; never silent continue; never auto-buy more GPU (`AUTO_GPU_PURCHASE=false`).
