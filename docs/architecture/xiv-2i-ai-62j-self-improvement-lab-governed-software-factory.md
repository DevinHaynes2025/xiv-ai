## Architecture contracts (story §§1–79)

### 1. XSIL — XIV Self-Improvement Lab

**XSIL** is the governed plane where XIV observes its own engineering signals, proposes improvements, and runs **sandbox-only** experiments.  
XSIL is **not** a production deployer, not a main-branch merger, and not a permission expander.  
All XSIL outputs are Improvement Records, experiment artifacts, evidence bundles, or draft PRs labeled **LAB / CANDIDATE**.

### 2. Engineering Agent Civilization

An **Engineering Agent Civilization** is a bounded set of specialized engineering agents (code, architecture, test, breaker, security, performance, dependency, UI/mobile, DB) coordinated under Guardian and human authority.  
Civilization ≠ unbounded replication. Agent count, roles, and blast radius are budgeted.  
Compose with **62I Foundry** for role minting — Foundry may propose teams; XSIL may not auto-grant production rights.

### 3. Dynamic Teams (62I Foundry)

**Dynamic Teams** are ephemeral role graphs spun by **62I Adaptive Agent Foundry** for a single Improvement Record or experiment family.  
Team charter includes: allowed paths, denied zones, budget, max agents, kill switch, and human owner.  
**Compose with 62I Night Shift / Foundry** — do not redefine Foundry here; **do not overwrite 62I docs**.

### 4. XIDE — Improvement Discovery Engine

**XIDE** observes: incidents, flake rates, latency regressions, tech-debt registry entries, rejected ideas, architecture health scores, customer/ops signals (when authorized), and overnight lab findings.  
Discovery emits **candidate observations** only — never code changes.  
Every observation carries provenance, confidence, and “unknown ≠ zero impact” honesty.

### 5. Improvement Record states

Canonical states (docs contract):

| State | Meaning |
|-------|---------|
| `OBSERVED` | Signal recorded; no work started |
| `HYPOTHESIZED` | Testable claim attached |
| `EXPERIMENTING` | Sandbox / lab run in progress |
| `MEASURED` | Metrics + evidence attached |
| `DEBATED` | Pro/con AI debate complete |
| `INDEPENDENTLY_VERIFIED` | Separate verifier pass/fail recorded |
| `HUMAN_REVIEW` | Package awaiting human |
| `MERGE_CANDIDATE` | Eligible for human-approved merge only |
| `MERGED` | Human-approved merge occurred (outside this park’s auto scope) |
| `REJECTED` | Closed with learning capture |
| `DEFERRED` | Time-aware retest scheduled |
| `BUDGET_BLOCKED` | Experiment budget exhausted |

Illegal transition: any state → production deploy without human + Guardian gates.

### 6. Hypothesis-Driven Development

Every experiment requires a **Hypothesis Card**: claim, measurable success/fail criteria, protected invariants, blast radius, rollback story, and stop conditions.  
No hypothesis → no sandbox write.  
Success metrics must include **anti-gaming** checks (§69).

### 7. XEE — Experiment Engine

**XEE** schedules and isolates experiments: environment, branch, resource caps, timeouts, telemetry sinks.  
XEE may run many parallel labs; it may **never** promote results.  
Failure of isolation = experiment abort + audit event.

### 8. Parallel Architecture Experiments

Multiple architecture variants may compete on the same Improvement Record (A/B/C design forks) inside sandboxes.  
Variants share the same Hypothesis Card family and Multi-Objective Score rubric.  
Winner = ranked **candidate**, not auto-adopted production architecture.

### 9. Sandbox Branch Factory

Creates ephemeral branches / worktrees with naming `lab/62j/<record-id>/<variant>` (convention only — not implemented here).  
Factory stamps: owner agent, file-scope ACL, expiry, budget remaining, Guardian policy snapshot.  
Expiry → auto-archive proposal (human confirm to delete); never force-push protected refs.

### 10. Branch Ownership

Every lab branch has exactly one **Branch Owner** (agent id + human sponsor).  
Ownership ≠ unlimited authority: owner cannot expand file-scope, weaken security policy, or merge to main.  
Orphaned branches are kill-switch targets.

### 11. File-Scope Controls

Agents receive an allowlist/denylist of paths. Writes outside scope are hard-denied and audited.  
Default deny. Scope expansion requires human + Guardian — `AUTO_PERMISSION_EXPANSION=false`.

### 12. Protected Zones

Permanent protected zones (non-exhaustive contract): Guardian configs, auth/RLS policies, billing/money movement, production deploy pipelines, secret stores, identity/trust roots, kill-switch controllers, this series’ security locks.  
Protected-zone touch attempts → immediate abort + Security Agent alert.

### 13. Code Agents

Implement sandbox diffs only within file-scope. Must attach Story-to-Code Traceability links.  
May not self-approve, self-merge, or disable tests.  
Output: patch + rationale + risk notes.

### 14. Architecture Agents

Propose structure, boundaries, ADRs, and health-score impacts — not silent refactors.  
Architecture Agent recommendations enter Innovation Backlog / Experiment Budget before code.  
May not evolve away Evolution Boundary constraints (§30).

### 15. Drift Detector

Compares sandbox intent vs actual diff, declared scope vs touched files, ADR vs implementation, and schema draft vs no-migration rule.  
Drift above threshold → Breaker/Security review; blocks MERGE_CANDIDATE.

### 16. Story-to-Code Traceability

Every changed file/hunk maps to: Improvement Record id, hypothesis id, story/queue id, test ids, and evidence bundle id.  
Missing traceability → DoD Compiler fail.

### 17. Test Agent

Generates/selects tests for the hypothesis; runs Continuous Testing Mesh subset.  
Critical suites (§32) are mandatory and non-skippable.  
Test Agent cannot mark flaky-critical as waived without human.

### 18. Breaker Agent

Adversarial/chaos attempts inside sandbox: fault injection, partial failure, dependency outage, race, poison metrics.  
Breaker pass is required evidence for MERGE_CANDIDATE on reliability-sensitive records.  
Breaker never runs against production.

### 19. Security Agent

Static/policy checks: secrets, authz, supply-chain, protected-zone touches, policy-weakening diffs.  
Security Agent veto is sticky until human override with audit — `AUTO_GUARDIAN_OVERRIDE=false` / `AUTO_SECURITY_POLICY_WEAKENING=false`.

### 20. XPL — Performance Lab

Sandbox performance harness: latency, throughput, memory, error budgets, cost signals.  
Unknown cost = UNKNOWN ≠ 0.  
XPL results feed Multi-Objective Score; they do not alone authorize merge.

### 21. CPU / GPU competition

Variants may compete under CPU-bound and GPU-bound profiles with explicit resource caps.  
Competition ≠ infra purchase. `AUTO_INFRASTRUCTURE_PURCHASE=false`.  
Results labeled SIMULATED/BENCH ≠ PRODUCTION SLA claims.

### 22. Quantum Research Branch

Optional research fork for quantum/hybrid algorithm exploration (compose LA-12 honesty).  
Always research/sandbox labeled; never production quantum claims from this park.  
Budget-capped; may produce Innovation Backlog entries only.

### 23. Algorithm Evolution

Evolutionary search over algorithms inside Arena — population, mutation, selection under Multi-Objective Score.  
Evolution operators cannot mutate Guardian, isolation, human-review gates, budgets, audit, or provenance (§30).  
Survivors = candidates for Human Review, not live swaps.

### 24. Algorithm Tournament

Scheduled head-to-heads with frozen rubrics, seeds, and datasets.  
Tournament leaderboard is advisory. Cheating/metric gaming → disqualification (§69).

### 25. Algorithm Arena

Shared evaluation substrate: fixtures, generators, replay, Regression Memory hooks.  
Arena isolation from production data unless explicitly synthetic/authorized snapshots.

### 26. Multi-Objective Score

Weighted vector: correctness, security, performance, cost, maintainability, blast-radius, human-review burden, evidence strength.  
Single-metric optimization forbidden for MERGE_CANDIDATE.  
Weights are human-governed; agents may propose, not silently change, weights.

### 27. Model Lab

Sandbox evaluation of models/prompts/tools for engineering tasks (compose 62I / model registries).  
Model enable/install AUTO flags remain FALSE. Lab ≠ production model router change.

### 28. Model Tournament

Comparative eval of candidate models for a task class under fixed suites.  
Winner is a recommendation for Human Review package — not auto-cutover.

### 29. Agent Tournament

Competing Dynamic Teams on the same Improvement Record under equal budgets.  
Replication beyond budget = Agent Explosion Test fail (§70). `AUTO_AGENT_REPLICATION=false`.

### 30. Evolution Boundary

**Hard non-evolvable set:** Guardian supremacy, isolation boundaries, human review requirement, experiment budget caps, audit logging, provenance chains, protected zones, kill switch, L4=false defaults, AUTO_* false defaults.  
Any proposal to weaken these is **reject-by-default** and Security-Agent-escalated.  
Self-improvement may improve *within* the boundary; it may not erase the boundary.

### 31. Continuous Testing Mesh

Layered always-on lab testing: unit → contract → integration → breaker → security → performance → overnight safety.  
Mesh runs in lab/CI sandbox contexts only for this park’s scope.  
Green mesh ≠ production authorization.

### 32. Test Selection (critical mandatory)

Critical suites (auth, RLS, money, Guardian, deploy gates, kill switch, migration safety stubs) are **mandatory** for relevant records and cannot be deselected by agents.  
Non-critical selection may be risk-based for speed, with rationale in Evidence Bundle.

### 33. Regression Memory

Stores past failures, flakes, and “fixed but returned” signatures.  
New candidates must consult Regression Memory; repeating a known failure class without mitigation blocks MERGE_CANDIDATE.

### 34. Failure Knowledge Base

Curated KB of root causes, mitigations, and false leads — including learnings from Rejected Ideas (§60).  
KB writes are auditable; KB is not an authority to skip tests.

### 35. Overnight Engineering Shift

Scheduled off-hours lab shift (compose **62I Night Shift**): Dynamic Teams process OBSERVED→MEASURED within caps.  
Overnight Shift **may not** merge, deploy, migrate, purchase, create external accounts, or weaken policy.  
Kill switch and budget caps always on.

### 36. Overnight output (0 production changes)

Mandatory morning package: Improvement Records touched, experiments run, failures, evidence links, draft PRs (if any), **explicit statement: production changes = 0**.  
Any overnight production write is Overnight Safety Test fail (§71) and Security Lock violation.

### 37. XSF — Software Factory

**XSF** turns MERGE_CANDIDATE packages into governed engineering artifacts: DoD checks, PR drafts, evidence, verifier stamps.  
Factory conveyor stops before human merge. `AUTO_MAIN_BRANCH_MERGE=false`.

### 38. DoD Compiler

Compiles Definition-of-Done checklist from record type: tests, security, traceability, drift, budget, Evolution Boundary attestation, anti-gaming attestation.  
Fail-closed: missing item → not MERGE_CANDIDATE.

### 39. PR Factory

Creates **draft** PRs only, with labels `lab`, `62j`, `not-automerge`, and Evidence Bundle link.  
No auto-approve, no auto-merge, no tip-land. Base branch policy remains human-controlled (`xiv-v2` / story bases as humans decide later).

### 40. Evidence Bundle

Immutable-ish package: hypothesis, diffs summary, test results, breaker/security/XPL outputs, Multi-Objective Score, debate transcript ids, verifier report, overnight notes, provenance.  
Bundle required for Human Review. Incomplete bundle = block.

### 41. Independent Verifier

Separate agent/process (no shared scratch with implementers) re-runs critical checks and samples claims.  
Collusion patterns (identical unchecked claims) fail Metric-Gaming / integrity rules.  
Verifier cannot merge.

### 42. AI Debate

Structured pro/con debate on MERGE_CANDIDATE readiness: benefits, risks, alternative, Evolution Boundary impact.  
Debate transcript attaches to Evidence Bundle. Debate ≠ decision; humans decide.

### 43. Human Review package

Reject → Learning from Rejected Ideas. Accept → human-driven merge path outside AUTO_*.
