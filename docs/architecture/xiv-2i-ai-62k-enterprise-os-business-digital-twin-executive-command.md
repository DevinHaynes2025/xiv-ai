## Architecture contracts (story §§1–102)

### 1. XEOS — XIV Enterprise Operating System

**XEOS** is the governed operating plane that holds enterprise registry, twin, hospital, command, workflow, and action-gateway contracts for **one isolated company universe**.  
XEOS is **not** a legal CEO, not a bank, not an HRIS of record, not an ERP replacement, and not a license to control a company.  
All XEOS outputs are observations, reconstructions, recommendations, drafts, or gated Action Contracts. Names of services ≠ capabilities.

### 2. Enterprise System Registry

The **Enterprise System Registry** catalogs candidate and connected systems (ERP, CRM, WMS, HRIS, bank-read, ticketing, data warehouse, identity, plugins) per tenant.  
Registry entry states: `UNKNOWN` | `DISCOVERED` | `CATALOGED` | `CREDENTIAL_BOUND` | `CONNECTED_READ` | `CONNECTED_WRITE` | `REVOKED` | `QUARANTINED`.  
**DISCOVERED ≠ CONNECTED ≠ AUTHORIZED ≠ WRITE.** Auto-connection is forbidden (`AUTO_ENTERPRISE_CONNECTION=false`).

### 3. Enterprise Domains

Canonical domains (document): Finance, HR, Procurement, Customer, Product, Operations, Supply Chain, Security, Legal/Contract, Technology, Knowledge, Cost/ROI.  
Each domain has: owner role, data class, freshness SLO (target, not claimed), write class, and isolation boundary.  
Domain presence in the registry ≠ live connector ≠ cross-domain join rights.

### 4. Connection States

Connection is a **state machine**, not a boolean.  
Read connections require explicit adapter, credential vault, purpose, retention, and audit.  
Write connections are a separate authorization and default **deny**. Stale / unknown / failed health checks degrade to `DEGRADED` or `UNKNOWN` — they do **not** stay “connected enough to write.”

### 5. XBDT — XIV Business Digital Twin

**XBDT** is the company digital twin: a governed model of entities, relations, and temporal state used for diagnosis, simulation, and briefing.  
**DIGITAL TWIN ≠ ACTUAL COMPANY.** Twin mutation in sandbox ≠ production mutation. Logical completeness ≠ perfect reality.  
Compose LA-25 Company Twin honesty; do not replace LA-25. 62K adds the XEOS/XEC/XEAG command-and-action contracts around the twin.

### 6. Entity Graph

The **Entity Graph** holds typed nodes (org unit, SKU, supplier, customer-account **minimized**, employee-role **non-surveillance**, contract-ref, asset, process, location) and typed edges.  
Missing nodes remain `UNKNOWN`. The graph must not invent entities to look complete.  
Customer and people nodes are **minimized, purpose-bound, and isolated** — graph convenience ≠ surveillance license.

### 7. Temporal State

Every twin fact is **bitemporal**: `valid_at` (world time) and `known_at` (when XIV learned it).  
Corrections create new known_at rows; they do not silently rewrite history.  
Future timestamps cannot enter `as_known_then` reconstructions. Compose LA-09 / LA-60D: no future leakage.

### 8. Business Event Mesh

The **Business Event Mesh** is the nervous system of authorized enterprise events (orders, exceptions, inventory deltas, tickets, payments-as-signals, approvals, connector heartbeats).  
**EVENT ≠ TRUTH.** Duplicate, delayed, partial, and conflicting events are first-class.  
Mesh subscribers are least-privilege; a hospital detector may see symptoms without gaining write adapters.

### 9. State Reconstruction

State Reconstruction builds **as-known-then** snapshots for diagnosis, audit, and counterfactuals.  
Reconstruction ≠ live entitlement. Cached ≠ live. Replayed events cannot smuggle later knowledge into earlier states.  
If sources disagree, reconstruction records **conflict**, not a silent winner.

### 10. XBHE — XIV Business Hospital Engine

**XBHE** is the Business Hospital: a **business metaphor only** (not practicing medicine) for intake, triage, diagnosis discipline, treatment options, and recovery tracking.  
Hospital cannot grant production write rights, money movement, hiring, or contract execution.  
Compose LA-25 / 2I-CD hospital metaphor; 62K specifies command-grade recommendation contracts and action gating.

### 11. Symptoms

A **symptom** is an observed deviation or risk signal with provenance, freshness, coverage, and confidence.  
Symptoms are **not** diagnoses, not root causes, and not authorization to treat.  
Every symptom carries: source, window, baseline honesty, UNKNOWN gaps, and detector identity.

### 12. Symptom Detector

The **Symptom Detector** watches Event Mesh + twin metrics + freshness/reliability signals and emits symptom records.  
Detectors may cluster related symptoms but **must not** auto-promote a cluster to a diagnosis.  
Detector silence ≠ health (see UNKNOWN ≠ HEALTHY).

### 13. No Auto-Diagnosis From One Signal

**Hard rule:** one metric, one alert, one agent opinion, or one customer complaint **cannot** become a diagnosis.  
Diagnosis requires Diagnostic Task Force (or documented equivalent multi-source workflow) plus Evidence Strength above a deny-safe threshold — still labeled **hypothesis** until human/policy accept.  
Single-signal “root cause” claims are a **FAIL class**.

### 14. Diagnostic Task Force

A **Diagnostic Task Force** is a bounded, ephemeral agent+human team (compose 62I Foundry Dynamic Teams / 62E task forces) chartered for one hospital case.  
Charter includes: allowed domains, denied write classes, budget, max agents, kill switch, human owner.  
**MORE AGENTS ≠ MORE AUTHORITY.** Task force consensus ≠ truth.

### 15. Diagnostic Workflow

Canonical workflow (docs): `INTAKE → TRIAGE → SYMPTOM SET → MULTI-SOURCE GATHER → DIFFERENTIAL → ROOT CAUSE GRAPH → EVIDENCE STRENGTH → HUMAN CHECKPOINT → CASE STATE`.  
Stages only advance with evidence pointers. Closed/quarantined cases do not silently reopen as healthy.  
Workflow names ≠ automated execution of treatments.

### 16. Root Cause Graph

The **Root Cause Graph** maps competing causal hypotheses with supporting/contradicting evidence and explicit unknowns.  
**AFTER ≠ BECAUSE. CORRELATION ≠ CAUSATION.** Multiple viable causes may remain open.  
A single highlighted “cause” without alternatives and unknowns is incomplete and must not drive consequential actions.

### 17. Evidence Strength

Evidence Strength is a structured grade (document classes): `UNGROUNDED` | `SINGLE_SOURCE` | `CORROBORATED` | `CONTRADICTED` | `INDEPENDENTLY_VERIFIED` | `UNKNOWN`.  
Strength ≠ permission. Independently verified still ≠ production write.  
Gaming strength (hiding contradictions, dropping unknowns) is a security/test FAIL class.

### 18. Treatment Engine

The **Treatment Engine** proposes **options** (process change, inventory policy, staffing request, vendor alternate, software experiment via 62J lab, communication, do-nothing).  
Every option lists: intended effect, blast radius, restrictions, rollback, required authority, residual risk, and UNKNOWN.  
Treatment proposal ≠ production surgery.

### 19. Treatment Restrictions

Restrictions are deny-by-default gates: no money movement, no contract bind, no hiring/termination, no permission expansion, no production deploy, no Guardian override, no cross-tenant data, no customer-super-join.  
A treatment that requires a forbidden class is **blocked**, not “queued as if approved.”  
Restrictions are non-evolvable by hospital agents.

### 20. Simulation

Simulation evaluates treatment options and shocks against the twin / process twin / playground.  
**SIMULATION ≠ REALITY ≠ FUTURE ≠ AUTHORITY.** Simulation agents never receive production credentials.  
Compose 62J sandbox honesty and LA-10 / LA-38 / LA-60Y: sim success ≠ verified savings.

### 21. Treatment Comparison

Comparison tables options on: expected operational effect (labeled projected), risk, cost class, reversibility, evidence strength, authority required, and unknowns.  
There is always a **do-nothing / watch** option. Ranking ≠ executive order.  
Hidden options (especially “do nothing”) are a FAIL class.

### 22. Counterfactual

Counterfactuals ask “what would have happened if…” on reconstructed state — labeled **counterfactual**, never as rewritten history.  
Counterfactual ≠ historical fact. Cannot be used to assign personal blame or to auto-punish.  
Future leakage into counterfactual baselines is forbidden.

### 23. Executive Recommendation Contract

The **Executive Recommendation Contract** is the only hospital→command payload: situation, symptom set, differentials, preferred option, alternatives, non-actions, evidence, unknowns, required human role, consequential class, expiry, and explicit **not authorized to execute**.  
Contract ≠ PO, ≠ wire, ≠ hire, ≠ terminate, ≠ production change.  
Expired contracts must be re-issued; stale recommendations cannot be executed.

### 24. XEC — XIV Executive Command

**XEC** is the Executive Command surface: briefs, queues, authority map, decision center, storytelling, control-tower views.  
XEC **presents and routes**; it does not silently execute irreversible commitments (compose 2I-CE).  
Founder Twin / CEO Copilot ≠ actual Founder/CEO authority. Company AI CEO title ≠ legal CEO.

### 25. Morning Brief

Morning Brief packages overnight intelligence: what changed, what is unknown, what was **not** done, budget consumed, top risks, recommendations awaiting humans.  
Overnight ≠ extra authority. Brief send (e.g. Founder address) remains `NOT_CONFIGURED` until a later verified story.  
A brief that omits non-actions or unknowns is incomplete.

### 26. Storytelling

Story Engine turns evidence into a **narrative for humans** (compose LA-15 / 2I-CB): story ≠ truth; new story = data ≠ authority.  
Stories must cite evidence pointers and preserve contradictions.  
Narrative polish cannot upgrade Evidence Strength.

### 27. Story Timeline

**Story Timeline** is an auditable sequence of events, decisions, recommendations, and outcomes for a case or period.  
Timeline order ≠ causation. Edits are append-only corrections with provenance.  
Timelines are tenant-isolated; they are not a public media feed (media graph is **62L**, not here).

### 28. Enterprise Workflow OS

Workflow OS holds named business workflows (quote-to-cash assist, exception handling, onboarding drafts, hospital cases, approval chains) with **authority levels** attached to each step.  
Workflow running ≠ authorization. Template installed ≠ write adapter.  
Compose LA-29 24/7 org: always-on analysis ≠ always-on execution.

### 29. Authority Levels

Authority is explicit and least-privilege (document ladder): observe → draft → recommend → bounded-low-risk-act → human-gated consequential act.  
**L4 DISABLED.** Agents cannot mint themselves a higher level. Learning / overnight / NL cannot raise authority.  
Compose 62H ownership: observation ≠ authority.

### 30. Read Before Write

**Read Before Write** is mandatory: no write adapter, Action Contract, or consequential class may proceed unless a successful authorized read/recon of relevant state exists **and** is fresh enough per policy — else state is UNKNOWN and write is denied.  
Read success ≠ write grant.  
This is the default enterprise posture of 62K.

### 31. Read Before Write Phases

Phases (docs): `DISCOVER → CATALOG → BIND CREDENTIAL → READ PROBE → FRESHNESS/PROVENANCE CHECK → HUMAN WRITE GRANT → ACTION CONTRACT → IDEMPOTENT APPLY → VERIFY OUTCOME → LEARN`.  
Skipping phases is a FAIL class. Failed verify rolls to quarantine recommendation, not retry storms.

### 32. XEAG — XIV Enterprise Action Gateway

**XEAG** is the sole gateway for enterprise-side effects. Agents do not call vendor APIs directly.  
Gateway enforces Action Contract, idempotency, consequential class, isolation, budget, and Guardian.  
Gateway down ≠ offline extra authority.

### 33. Action Contract

An **Action Contract** names: actor, tenant, purpose, domain, idempotency key, blast radius, consequential class, evidence pointer, approving human/policy, expiry, rollback.  
Unsigned / expired / class-mismatch contracts are denied.  
Draft Action Contract ≠ executed action.

### 34. Idempotency

All gateway applies are idempotent on `(tenant, idempotency_key)`.  
Retries must not double-order, double-pay, double-message, or double-provision.  
Missing keys → deny. Idempotency ≠ permission to replay a denied class.
