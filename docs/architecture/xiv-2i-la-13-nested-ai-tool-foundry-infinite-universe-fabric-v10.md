### 3. Tools-building-tools (nested generation)

Tools may generate or compose child tools **only** under Foundry contracts.

| Contract | Detail |
|----------|--------|
| **No unrestricted perms** | Generator cannot mint ambient root, secrets, or L-levels |

### 4. Nested tool graph

**Types:** `NestedToolGraph`, `ToolNode`, `ToolEdge`, `ToolDepthLimit`, `ToolCycleGuard`.

- Graph records parent→child composition and invoke edges
- Depth and fan-out budget-bounded
- Cycles that would escalate privilege → DENIED + AUDITED
- Graph membership ≠ invoke rights

### 5. CompositeTool + own manifest

A `CompositeTool` **must** carry its **own** signed manifest — not an implicit union of child capabilities.

| Rule | Contract |
|------|----------|
| **Own manifest** | Declares composite purpose, inputs/outputs, max child set, permission ceiling |
| **Ceiling** | Effective perms ≤ composite manifest ∩ each invoked child ∩ caller grant |
| **No privilege union** | Assembling tools never OR-merges their grants into ambient power |
| **Failure** | Child deny → composite fail-closed unless explicit degrade path documented |

### 6. Tool permission model

Default: **NONE**. Grants are explicit, time-bounded where applicable, tenant/Universe scoped, and audited. Capability tokens for invoke; catalog listing ≠ invoke. Destructive / network / secret-adjacent scopes require elevated human/policy gates.
