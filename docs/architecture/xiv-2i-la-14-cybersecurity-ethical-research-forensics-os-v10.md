## Core ethical rule (must remain explicit — permanent)

### Ethical hacking scope (ONLY)

Ethical security research and testing are permitted **only** against:

1. **XIV-owned systems** (explicit inventory membership), or  
2. **Purpose-built labs / CTF / Cyber Range** environments designed for testing, or  
3. **Third-party systems** with **explicit written authorization**, **defined scope**, **time bounds**, and **Rules of Engagement (RoE)** recorded before any active test.

### Learning ≠ license

Learning from historical incidents, public advisories, licensed defensive curricula, CTF writeups, or published research **is not** permission to break into unrelated companies, scrape credentials, or probe random internet hosts.

### Absolute prohibitions

| Forbidden | Meaning |
|-----------|---------|
| **NO STEALING** | No theft of data, funds, IP, or access |
| **NO UNAUTHORIZED ACCESS** | No access outside authorized scope |
| **NO EXTORTION** | No threats, ransom, or coercive leverage |
| **NO DATA EXFILTRATION** | No removing customer/third-party data outside authorized evidence handling |
| **NO MALWARE** | No planting ransomware, backdoors, or persistent unauthorized code |
| **NO CREDENTIAL THEFT** | No harvesting, stuffing, or trafficking credentials |

### Scope honesty

| Rule | Contract |
|------|----------|
| **UNKNOWN scope = NO ACTIVE TESTING** | Ambiguous targets stay idle |
| **Publicly reachable ≠ authorized** | Internet exposure is not consent |
| **AI supervision ≠ legal authorization** | Models/agents cannot invent permission |
| **Expired Security Mission Token = STOP** | Time/scope expiry kills active work immediately |
| **Guardian above agents** | No agent outranks Guardian / human+policy authority |

Inherited from LA-13: **DEFENSIVE ≠ EXPLOITATION**; **PUBLIC WEBSITE ≠ ATTACK SURFACE BY DEFAULT**.

### 2. Authorization Gate

**Types:** `AuthorizationGate`, `AuthorizationArtifact`, `ScopeDocument`, `RoEBinding`, `AuthGateDecision`.

| Decision | Meaning |
|----------|---------|
| `ALLOW_SCOPED` | Explicit auth + scope + RoE + live token |
| `ALLOW_LAB_ONLY` | Lab/CTF/Cyber Range only |
| `DENY` | Missing/invalid/expired/out-of-scope |
| `UNKNOWN_HOLD` | Insufficient evidence of authorization — **no active testing** |

**Missing artifact ⇒ DENY / UNKNOWN_HOLD.** Gate runs **before** any active probe, scan that leaves lab, or researcher tool grant.

### 3. Target states

Every research/test target carries an explicit state:

| State | Meaning | Active testing |
|-------|---------|----------------|
| `XIV_OWNED` | On XIV ownership inventory | Allowed under internal RoE + token |
| `LAB` | Purpose-built lab | Allowed under lab RoE |
| `CTF` | Competition / training CTF | Allowed under CTF rules |
| `AUTHORIZED_THIRD_PARTY` | Written third-party auth | Allowed inside scope only |
| `AUTHORIZED_CUSTOMER` | Customer Security Center engagement | Allowed inside customer contract scope |
| `PUBLIC_BUG_BOUNTY_WITH_VERIFIED_SCOPE` | Public bounty **and** verified program scope on file | Allowed inside verified bounty scope only |
| `OUT_OF_SCOPE` | Explicitly excluded | **Forbidden** |
| `UNKNOWN` | Not classified | **NO ACTIVE TESTING** |

**Publicly reachable ≠ `AUTHORIZED_*`.** Classification requires evidence, not inference.

### 4. Rules of Engagement (RoE)

**Types:** `RulesOfEngagement`, `RoEClause`, `AllowedTechnique`, `ForbiddenTechnique`, `EmergencyStopClause`.

RoE must define: in-scope assets, out-of-scope assets, allowed techniques, forbidden techniques (e.g. DoS, social-engineering of humans without explicit permit, malware, exfil), data handling, disclosure path, emergency contacts, kill-switch triggers, and time bounds.

**No RoE ⇒ no active testing** (except read-only defensive inventory of XIV_OWNED under separate internal policy — still tokenized).

### 5. Human researcher marketplace

**Document:** `EthicalHackerMarketplace`, `ResearcherProfile`, `EngagementOffer`, `EngagementContractRef` (LA-15 depth).

Marketplace matches **authorized** work only. It is **not** a gray-hat freelance break-in board. Payments (when any) flow only through **authorized workflow** (bug bounty foundation / commerce plane) — never cash-for-silence.

### 6. Trusted Researcher Program

**Types:** `TrustedResearcher`, `ResearcherVetting`, `ResearcherClearanceLevel`, `ResearcherSuspension`.

Vetting covers identity assurance (as policy allows), past conduct, skill evidence, agreement acceptance, and continuous reputation. Clearance ≠ ambient root on customer systems. Suspension/revocation is immediate on policy breach.
