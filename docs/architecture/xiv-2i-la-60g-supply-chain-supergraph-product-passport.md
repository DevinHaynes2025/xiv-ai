## Architecture contracts (story §§1–161)

### 1. MISSION

Unify PHYSICAL + INFORMATION + TECHNOLOGY supply chains into one governed temporal **SupplyChainSupergraphV100** without collapsing tenant, security, rights, or classification boundaries.

**Mission statement:** Trace any business outcome backward and forward across:
1. the **physical** journey of materials and products;
2. the **information** journey that informed decisions;
3. the **technology** journey that carried, stored, computed, and secured that information.

**Non-goals (this story):** economic digital twin / world business simulation civilization depth (**LA-60H**); inventing full **LA-60H–60P** docs; runtime implementation; L4 autonomy; money movement; fake GPS; partnership claims for marketplace adapters.

### 2. THREE SUPPLY CHAINS

XIV maintains three first-class supply-chain planes:

| Plane | Canonical chain |
|-------|-----------------|
| **Physical** | MATERIAL → SUPPLIER → FACTORY → PRODUCT → WAREHOUSE → TRANSPORT → PORT → MARKETPLACE → CUSTOMER → OUTCOME |
| **Information** | SOURCE → CONNECTOR → INGESTION → DATABASE → KNOWLEDGE → BRAIN → AGENT → DECISION → OUTCOME |
| **Technology** | DEVICE → SOFTWARE → API → MODEL → DATABASE → CLOUD → NETWORK → PROVIDER → BUSINESS WORKFLOW → OUTCOME |

**PHYSICAL ≠ INFORMATION ≠ TECHNOLOGY.** Edges may *connect* planes; connection never collapses classification or trust.

### 3. SUPPLYCHAINSUPERGRAPH V100

**SupplyChainSupergraphV100** is the governed temporal multi-plane graph uniting the three chains.

Capabilities (architecture):
- multi-plane node families (physical / information / technology / identity / commercial / risk);
- temporal edges with `valid_from` / `valid_to` / `recorded_at`;
- evidence, source, confidence, rights, classification on every claim edge;
- company-bound vs global-lawful partitions;
- causal candidate edges distinct from mere graph paths;
- story overlays via SupplyChainStoryEngineV50 (story ≠ causal proof).

**CURRENT RELATIONSHIP ≠ HISTORICAL RELATIONSHIP.** Supergraph must retain both.

### 4. NODE FAMILIES

Node families include (non-exhaustive): Material, Supplier, Factory, SKU/Product, Lot/Batch, Warehouse, Bin/Location, Carrier, Shipment, Port, MarketplaceListing, CustomerOrder, Return, Passport, Claim, Source, Connector, Dataset, KnowledgeNode, Brain, Agent, Decision, Device, SoftwareComponent, API, Model, CloudResource, NetworkPath, Provider, SBOMComponent, RiskSignal, SimulationRun, Story, Forecast, Invoice, Quote, RFQ, ContractCandidate.

Every node carries: identity keys, tenant/universe scope, classification, rights passport reference, temporal validity, evidence refs, confidence, provenance.

### 5. TEMPORAL EDGES

Edge contract fields (minimum):
- `edge_type`
- `valid_from` / `valid_to` (business-valid time)
- `recorded_at` (system knowledge time)
- `source` / `evidence_ids`
- `confidence`
- `rights` / `license` / `classification`
- `actor` / `authority_level`
- `supersedes` / `contradicts` (optional)

**CURRENT RELATIONSHIP ≠ HISTORICAL.** Closing an edge never erases history; it sets `valid_to`.

### 6. CURRENT RELATIONSHIP != HISTORICAL

Hard ban: treating the latest edge as the only truth. Queries must declare as-of mode:
- **AS_OF_NOW** (current open edges)
- **AS_OF_T** (business-valid at T)
- **KNOWN_AT_T** (what system knew at T — recorded_at ≤ T)
- **HINDSIGHT** (explicit, labeled; never default)

Wrong forecasts and superseded supplier links remain in history (§§124–125, §161).

### 7. GLOBAL PRODUCT PASSPORT V50

**GlobalProductPassportV50** extends LA-21 with Supergraph binding:
- passport id, product identity graph refs, lot/batch lineage, supplier/factory evidence, authenticity signals, rights, classification, marketplace listing refs, image evidence refs (AI image ≠ product evidence), history timeline.

**PRODUCT PASSPORT ≠ OWNERSHIP PROOF.** Passport attestations are evidence-bearing claims, not title deeds.

### 8. PRODUCT PASSPORT != OWNERSHIP PROOF

Passport may include ownership *claims* with evidence and rights, but never auto-promote to legal ownership. Commerce listing and passport are distinct objects. Transfer of listing ≠ transfer of passport ownership semantics without contract + authority gates.

### 9. PRODUCT IDENTITY GRAPH

**Product Identity Graph** resolves: brand+name, GTIN/UPC/EAN, SKU, MPNs, marketplace ASINs/item ids, internal product ids, lot/batch, serial, image fingerprints, passport ids.

**SAME PRODUCT NAME ≠ SAME PRODUCT.** Entity resolution requires multi-key evidence; ambiguous matches stay UNKNOWN / CANDIDATE.

### 10. SAME PRODUCT NAME != SAME PRODUCT

Hard ban on collapsing identity by display name or fuzzy brand string alone. Require corroboration thresholds; preserve competing candidate identities until verified.

### 11. PRODUCT IMAGE CLASSIFICATION

Image pipeline classifies: packaging photo, lifestyle photo, AI-generated marketing image, user review image, warehouse scan image, authenticity reference image.

Each class carries different evidence weight. Synthetic / generative images are labeled.

### 12. AI IMAGE != PRODUCT EVIDENCE

AI-generated or heavily edited images cannot alone substantiate physical product identity, authenticity, or condition. They may illustrate marketing claims only with explicit labels.

### 13. PRODUCT HISTORY

Product History timeline: design → sourcing → manufacture → quality events → warehouse → transport → listing → sale → return → disposal/recycle — plus information and technology events that affected decisions about the product.

History is append-only with revision memory; updates never silently erase prior beliefs.

### 14. SUPPLIER IDENTITY GRAPH V50

**SupplierIdentityGraphV50**: legal entity, trade names, addresses, tax ids (rights-gated), facilities, certifications (claimed vs verified), contact channels, ownership links, risk flags, verification state machine.

States: DISCOVERED → CANDIDATE → UNDER_REVIEW → VERIFIED → MONITORED → SUSPENDED → BLOCKED → ARCHIVED.

### 15. SUPPLIER VERIFICATION STATES

Verification is multi-factor: registry match, document evidence, facility evidence, trade history, sanctions/compliance screens (lawful), human/authorized review for high-risk tiers.

**SUPPLIER DISCOVERED ≠ VERIFIED.** Discovery agents cannot self-promote to VERIFIED.
